## Контракт для нового приложения

**Заголовки на каждом запросе:** `x-kstati-api: 2` и `x-kstati-app: ru.kstati.app/<версия>(<сборка>)`. Без `x-kstati-api` сервер считает клиента старым (уровень 1). Перед работой проверить `GET /health` → `api >= 2`.

**Хотелки (S1).**
- Отметить чужую хотелку: `{ op: 'wish.gift', ownerId, id, gifted: true }`. Можно, если с владельцем есть общая группа. Ошибки: `own_wish` (своя — через `wish.put` с `receivedAt`), `forbidden` (нет общей группы), `not_found`, `already_gifted` (уже подарил другой или владелец уже получил). Повтор той же отметки — `ok`.
- Снять: `gifted: false`. Только тот, кто подарил (`forbidden` для остальных), и только пока владелец не отметил «получил» (`received`).
- В `/sync` у чужих хотелок: `giftedBy` (id), `giftedAt`. «Подарено · от Х» = есть `giftedBy`. `receivedAt` — только отметка самого владельца.
- У своих хотелок `giftedBy`/`giftedAt` приходят, только когда стоит `receivedAt`. До этого полей нет вовсе.
- `wish.put` владельца: `giftedBy` можно не слать. Если прислать вместе с `receivedAt` — «от кого» (человек из общих групп, иначе `bad_member`; `null` — убрать). Пока `receivedAt` пуст, `giftedBy` от владельца игнорируется: скрытую отметку он стереть не может. Снял `receivedAt` (было → `null`) — подарок снимается у всех.
- `wish.gift` не меняет `updatedAt` хотелки (по нему владелец догадался бы), но поднимает ревизию владельца. В ленту пишется обычное `wish.done` от имени дарителя; владелец свою ленту хотелок не видит.

**Темы идей (S2).** `topic.put` принимает `archivedAt`: строка — в архив, `null` — из архива, нет поля — не трогать. Менять может только владелец (тема пишется только в его идеи). В `/sync` поле есть только у темы в архиве. Участники видят архив владельца.

**Голос: повторы (S3).** В `changes[i]` для дела с повтором может прийти `occ: 'YYYY-MM-DD'` — раз серии, названный во фразе. Относится к `chosen`: выбрали другой вариант — `occ` не использовать.
- `delete`/`update`: ближайший существующий раз с сегодня в названный день недели или дату («удали йогу в субботу», «… 24 октября»). Удалённые разы (`skipDates`) пропускаются.
- `update`: исходный день ищется до первого «на / к» («перенеси йогу в субботу на воскресенье» → суббота). Для API 2 `patch.date` считается от `occ` (воскресенье после этой субботы), для старого — как раньше, от даты серии.
- `mark`/`unmark`: последний прошедший такой раз за неделю, иначе ближайший будущий.
- День не назван, новый повтор или «больше не повторяй» — `occ` нет: правка всей серии.
- «Только этот раз / все повторы» решает клиент: `deleteTask(id, occ)` → `skipDates`; перенос одного раза — `skipDates` + новое дело.

**Голос: планы (S4).** `queryPlans.plans`:
- `scope: { kind: 'me' }` — все мои группы, только мои дела. Сейчас всегда идёт вместе с `who: [мой id]`.
- `who?: ID[]` — чьи дела показывать (участие = `people`, а если `people` пуст — автор). Может прийти и с другим `scope`, если модель назвала человека.
- Многодневные дела, начавшиеся до периода, считает клиент (см. ниже).

**Счётчик голоса (S6).** `GET /voice/quota` → `{ limit, used, left }` за сегодня по Москве. Лимит не тратит.

**Язык (S7).** В `/voice`: `lang: 'ru-RU' | 'en-US' | 'auto'`, по умолчанию `ru-RU`; другое значение — 400 без списания лимита. Если SpeechKit v1 отклонит `auto` (400), сервер распознаёт по-русски. Поддержку `auto` в v1 надо проверить на живом ключе. Промпт русский: английские фразы будут разбираться хуже.

## Совместимость со старым приложением

- **Нет поля — значит не трогать.** `wish.put` без `giftedBy` и `topic.put` без `archivedAt` сохраняют прежние значения. Покрыто тестами `e2e.ts` и проверено мутацией: если убрать правило, тесты падают.
- **Новые поля — только `.optional()`.** Старый сервер выбросит их молча (zod), поэтому новое приложение со старым сервером не падает, но подарки и архив не сохранятся.
- **Новые виды ответа — только при `x-kstati-api >= 2`.** `scope: 'me'` и `who` старому клиенту не уходят: его `resolveGroups` (`mobile/src/lib/plans.ts`) на незнакомом `kind` падает с `TypeError`. Старый клиент на «что я делаю» получает `current`, как и раньше. Новых видов ленты и жанров нет.
- **Хотелки в старом приложении.** Владелец видит прежний набор полей. Остальным подарок показывается через `receivedAt = giftedAt`: хотелка уходит в «Подарено». Чужие хотелки старое приложение на сервер не шлёт, так что подставленное значение нигде не сохранится.
- **Поля, которые старое приложение просто не читает:** `occ` в `changes`, `archivedAt` у тем (архивная тема выглядит как обычная), `giftedBy` у получённой хотелки.
- «Я» в `people` больше не даёт «Не нашёл человека «Я»»: старому клиенту — текущая группа или остальные названные люди.

## Порядок выката

1. Сервер. Таблицы и данные не меняются, миграций нет. Проверить `GET /health` → `"api": 2`.
2. Прогнать `npm run eval` на живой модели: новые фразы и промпт.
3. Только потом выпускать новое приложение. Оно проверяет `/health.api >= 2` и шлёт заголовки S5.

## Что не делали и почему

- **S8 (VK, несколько схем), S9 (`group.create` в ленте), S10 (жанры)** — пропущены по решению.
- **Многодневные дела в ответе «что у нас на выходных»** считает клиент: `answerPlans` в `mobile/src/lib/plans.ts` фильтрует по `t.date` внутри периода и теряет дело, начавшееся раньше. В новом приложении нужно пересечение `[date, endDate]` с периодом (`lib/span.ts` `daysOf`). Сервер отдаёт только период и чьи дела.
- **Занятость и свободные окна** сервер не считает: это `lib/conflicts.ts` и `lib/free.ts` нового приложения. Дела «весь день» и многодневные там занятостью не считаются.
- **Цвет человека** уже есть (`profile.color`, общий во всех группах). Сервер не менялся.
- **Двойные напоминания** при двух приложениях на одном телефоне допустимы. Сервер не менялся.
