## Подробно

### С1. Нет группы: дело молча пропадает — серьёзно
**Где:** `src/lib/store.ts:581` (`else if (groupId)` — без группы дело не создаётся), `src/containers/editors/TaskEditorContainer.tsx:119-124`
(`saveDraft` → `leaveEditor` без проверки), `:88-95` (`makePlan`: `saveDraft` вернул `null` — ничего не происходит),
`src/containers/voice/actions.ts` `saveVoiceItem` (переходит на вкладку, будто сохранено), `src/containers/calendar/CalendarContainer.tsx`
(перехода на онбординг нет, а у `TasksListContainer.tsx:35` и `WatchContainer.tsx:69` он есть), `app/onboarding.tsx:34` («Позже» → `/wishes`),
`src/lib/api.ts:18` (`groupId: ''` в контексте голоса).
**Шаги:** регистрация → онбординг → «Позже» → ДЕЛА (по умолчанию вид НЕДЕЛЯ) → «+» → название → СОХРАНИТЬ. Или REC → «Купить хлеб завтра» → СОХРАНИТЬ.
**Ожидается:** дело сохранено, или понятно, что сначала нужна группа.
**Факт:** окно закрывается, дела нет, сообщения нет. При этом СМОТРЕТЬ и СПИСОК каждый раз выкидывают на онбординг (`Redirect` с `replace` выгружает вкладки),
а НЕДЕЛЯ / ДЕНЬ / МЕСЯЦ / ГОД — нет. Поведение непоследовательное.
**Исправление:** одно правило для «Дел»: `Redirect` на `/onboarding` в `CalendarContainer`, как в списке, либо пустое состояние с «Создать группу».
В окне дела при `draft.groupId == null` вместо сохранения — `notice('Сначала создайте группу')` + `setGroupSheet(true)`. В `saveVoiceItem` / `CardSheet.save`
проверять, что запись действительно добавилась.

### С2. Тема идей без нижней навигации — серьёзно
**Где:** `app/(tabs)/ideas/[id].tsx` — нет `<BottomNav>`. `tabBar={() => null}` в `app/(tabs)/_layout.tsx:14`, а старый общий `BottomBar` удалён.
При этом `:42` (`useFocusEffect` → `setVoiceTopic`) и `:88` (`paddingBottom: useBottomSpace()`) рассчитаны на навигацию.
**Шаги:** ИДЕИ → тема.
**Ожидается:** по INTEGRATION 2.1 и комментарию в `ideas/_layout.tsx` — «микрофон и вкладки остаются под рукой»; голос без названной темы кладёт идею в открытую тему.
**Факт:** нет ни REC, ни вкладок, снизу пустое поле 98 pt. Ветка `voiceTopicId` (`api.ts:18`) недостижима: REC есть только на других экранах, а там тема сброшена.
**Исправление:** добавить `BottomNav active="ideas"` с `useChrome('ideas')` (`onNavigate`, `onRec`) и учесть `RecButtonContext`, как на остальных экранах.

### С3. Второй экземпляр вкладок в корневом стеке — серьёзно (проверить на устройстве)
**Где:** `src/containers/editors/PlanEditorContainer.tsx:93` (`onOpenGrid` и пункт меню «План сеткой» → `router.push(nav.planGrid)` из корневого `edit/plan`);
`src/containers/lists/ActivityContainer.tsx:26` (`topic.share` → `router.push(nav.topic)` из корневого `/activity`); `src/components/TaskRow.tsx:163`
(`openPlan` из старого редактора в `CardSheet`).
**Шаги:** ДЕЛА → план (C-Plan) → ⋯ (C-EditPlan) → ⋯ → «План сеткой».
**Ожидается:** возврат к сетке.
**Факт:** с expo-router v4 `push` на маршрут из другого навигатора кладёт в корневой Stack новый `(tabs)`: `[(tabs), edit/plan, (tabs)]`.
Получаются два набора вкладок, два `BottomNav`, вечно растущий стек и «назад», который ведёт в старую копию. У ленты то же самое: она остаётся
смонтированной, поэтому `markActivitySeen` не вызывается до её закрытия.
**Исправление:** для целей во вкладках вызывать `router.navigate(...)` (или `dismissTo`). В окне плана: если предыдущий экран — сетка этого плана, вызывать `router.back()`.

### С4. Два окна одного плана с разными черновиками — серьёзно
**Где:** `src/containers/editors/TaskEditorContainer.tsx:149` («Открыть план» → `router.push(nav.planEditor(planId))`). Черновик окна плана
снимается один раз при открытии (`PlanEditorContainer.tsx:40`).
**Шаги:** C-EditPlan → подзадача → ⋯ → «Открыть план» → сдвинуть период → СОХРАНИТЬ → назад из подзадачи → в первом окне плана СОХРАНИТЬ.
**Ожидается:** новый период сохранён.
**Факт:** первое окно сохраняет свой старый черновик, и период откатывается.
**Исправление:** если подзадачу открыли из окна этого плана (`parentId` совпадает и `canGoBack`), «Открыть план» вызывает `router.back()`.
Иначе — `navigate`, а не `push`.

### С5. Корневой стек не сбрасывается при выходе, входе и по ссылке — серьёзно (проверить на устройстве)
**Где:** `src/containers/account/ProfileContainer.tsx:40, :54` (`router.replace('/login')` из `/settings`: стек `[(tabs), login]`), `app/login.tsx`
`after()` (`replace('/tasks')` → `[(tabs)старый, (tabs)новый]`), `app/record.tsx:13` (ссылка при работающем приложении: `[(tabs), record]` → `[(tabs), (tabs)]`).
**Факт:** под экраном остаются смонтированные вкладки прошлого входа: экраны с `NO_ME`, подписки и таймеры. Android «назад» ведёт в них.
**Исправление:** перед `replace` вызывать `router.dismissAll()`. Ещё лучше — `Stack.Protected guard={!!me}` в `app/_layout.tsx`. В `record.tsx` —
`router.dismissTo('/tasks')` / `navigate`.

### М1. C-Plan → СПИСОК выгружает вкладки — мелко
`src/containers/calendar/PlanContainer.tsx:43`: `router.replace(nav.planEditor(id))` из стека вкладки заменяет в корне весь `(tabs)`. После «назад»
`leaveEditor` видит `canGoBack() === false` и делает `replace('/tasks')`: вкладки монтируются заново, а стек «Идей» и прокрутка теряются.
**Исправление:** `router.push(nav.planEditor(id))`. «Назад» тогда вернёт в сетку, и это естественнее.

### М2. Серия удаляется целиком без вопроса — мелко
`TaskEditorContainer.tsx:131`: `if (!task.repeat || !d.occ) return removeTask(task.id)`. Без `occ` окно открывают лента (`ActivityContainer.tsx:32`),
шаги плана (`PlanContainer` `openStep`, `PlanEditorContainer` `onOpenSubtask`) и «Изменить» у отметки. Кнопка «Удалить» в этих случаях молча удаляет все повторы
(отмена есть только в тосте). **Исправление:** у серии без `occ` спрашивать «Удалить все повторы?» или брать `nextOpen` как раз по умолчанию.

### М3. Нет «Этот и все следующие» — мелко
В старом приложении было (`src/components/TaskRow.tsx:175`, `endSeries`). В новом окне дела (`TaskEditorContainer.tsx:133-139, :152-157`) есть
только «этот раз» и «все». Если это не намеренное упрощение, добавить третий пункт.

### М4. Окно ошибки голоса без «добавить вручную» — мелко
`voiceView` (`src/adapters/voice/view.ts:31`) отдаёт хосту все голосовые ошибки, поэтому старые ветки `CardSheet` `Problem` («Не понял → Дело / Хочу / Смотреть…»,
«Не нашёл → Добавить вручную») больше никогда не рисуются. `problemSheet` даёт только ЗАКРЫТЬ / ЕЩЁ РАЗ / НАСТРОЙКИ. Распознанную, но не понятую фразу
нельзя сохранить в одно касание. **Исправление:** у `notUnderstood` / `notFound` вторичная кнопка «ДОБАВИТЬ» → `setCard({ source: 'manual', items: [emptyDraft(...)] })`
(для дела — новое окно с `editorSeed`).

### М5. 401: выход без перехода на вход — мелко
`src/lib/sync.ts:293` вызывает `logout()` и никуда не переходит. Во вкладках `Redirect` в `(tabs)/_layout` сработает, но на `/settings`, `/group/…`, `/edit/task/…`
человек остаётся на экране с `NO_ME`, и «СОХРАНИТЬ» молча ничего не делает (`saveItems` при `!me` → `{}`). **Исправление:** в корневом макете следить
за `me` → `null` и делать `dismissAll` + `replace('/login')` (или `Stack.Protected`, см. С5).

### М6. C-Group: группа исчезла — пустой экран — мелко
`src/containers/account/GroupContainer.tsx:114`: `if (!data) return null` без ухода назад. Если меня исключили или группу удалили на другом телефоне,
после синхронизации экран пуст, кнопки «назад» нет. **Исправление:** `useEffect(() => { if (!data) back(); }, [data])`, как в `PlanContainer.tsx:33`.

### М7. «Новая группа» в профиле — мелко
`ProfileContainer.tsx:19`: `setGroupSheet(true)` открывает список групп (`GroupPanel initial='list'`). Чтобы создать группу, нужно ещё одно касание,
а случайный тап по группе в списке переключает текущую группу. **Исправление:** режим листа в store (`groupSheet: false | 'list' | 'create'`).

### М8. Лимит голоса из настроек не мешает записи — мелко
`SettingsContainer.tsx:51` кладёт счётчик через `fetchVoiceQuota` напрямую. `quotaDay` в `src/lib/voice.ts` при этом не ставится, и `quotaSpent()`
возвращает `null`. При «30 из 30» REC всё равно пишет до 10 с и только потом показывает лимит. **Исправление:** вызывать `refreshVoiceQuota()`.

### М9. «ВСЕ» в хотелках при API < 2 — мелко
`WishesContainer.tsx:78` передаёт `toggleGift` на вкладке «ВСЕ» всегда, а `toggleGift:24` при `!giftsOn` молча выходит. На старом сервере
(или пока `/health` не ответил, `serverApi === null`) отметка чужой хотелки на «ВСЕ» не реагирует. **Исправление:** в этом случае `notice('Сервер устарел')`
или не показывать отметку у чужих строк.

### М10. «ИЗМЕНИТЬ» во время записи — мелко
`VoiceHost.tsx:42-46`: флаг сбрасывается на первом `idle`. Если ответ — несколько записей, правка, вопрос о планах или ошибка, намерение «изменить»
пропадает молча, и показывается обычное окно. Это допустимо, но стоит проверить на устройстве: `setVoice('idle')` и `setCard` должны попадать в один рендер.

### М11. Код из письма: Android «назад» — мелко
`app/login.tsx` — шаг `code` рисует `CodeScreen` без `BackHandler`. Экран входа — корень стека, поэтому системное «назад» закрывает приложение.
**Исправление:** `BackHandler` на шагах `code` и `password` → предыдущий шаг.

## Что проверено и в порядке

- **Маршруты.** Каждый файл `app/**` что-то рисует. Контейнеров-заглушек `return null` нет: `null` возвращают только `PlanContainer`,
  `TaskEditorContainer` и `PlanEditorContainer`, и все трое сразу уходят назад. `Tabs.Screen` (`tasks`, `wishes`, `watch`, `ideas`) и `Stack.Screen`
  (`edit/task/[id]`, `edit/plan/[id]`) совпадают с файлами. Все цели `nav.*` и строковые адреса (`/login`, `/onboarding`, `/tasks`, `/wishes`, `/ideas`,
  `/ideas/<id>`, `/activity`, `/settings`, `/settings/*`, `/group/<id>`, `/edit/*`) существуют.
- **Колбэки.** Все колбэки экранов, у которых есть элемент на экране, переданы. Намеренно не переданы: поддержка и политика (`showAboutLinks={false}`),
  переименование и категория без прав, копирование кода без кода, подарки и архив при API < 2, открытие чужой хотелки.
- **Сценарий 1.** Почта → код (`CodeScreen`, проверка на 6-й цифре, повторная отправка через 60 с) → пароль → `syncNow` → онбординг или `/tasks`.
  Выход стирает данные (`emptyData`).
- **Сценарий 2.** `BottomNav` и REC есть на C-List, C-Day, C-Week, C-Month, C-Year, C-Plan, C-Wishes, C-Watch, C-Ideas (кроме темы — С2). ДЕНЬ / НЕДЕЛЯ /
  МЕСЯЦ / ГОД / СПИСОК переключаются через `s.tasksView`. Неделя → день, месяц → год, год → месяц, ‹ › и СЕГОДНЯ работают. Режим «удерживать» идёт через `RecButtonContext`.
- **Сценарий 3.** «Назад» выбрасывает черновик. Новое дело без названия сразу открывает ввод названия. Раз серии показывается своей датой, а сохраняется
  как сдвиг начала серии. «Только этот раз» → `skipDates`, с отменой.
- **Сценарий 4.** «Сделать планом» → окно плана + новая подзадача. Перенос периода не двигает подзадачи (`saveItems` без `shiftChildren`), вышедшие
  получают «ВНЕ ПЕРИОДА». Удалённый план закрывает C-Plan.
- **Сценарий 5.** Одна запись, одна правка, вопрос о планах и ошибки идут в `VoiceHost`, остальное — в `CardSheet` (одна функция `voiceView`, двойного показа нет).
  Лимит → «Лимит на сегодня: N из N» без «ЕЩЁ РАЗ». `kstatiapp://record` → окно «Записать команду?» (без автозаписи); без входа ведёт на `/login`.
- **Сценарий 6.** Подарок чужой хотелки: оптимистичная отметка, при отказе откат и тост. Своя хотелка остаётся в «Хочу» до «получил».
  Подарок в ленте → вишлист владельца (`wishOwnerOf` по `scope u:`). Фильтры «Смотреть» + `FilterSheet`. Архив тем.
- **Сценарий 8.** Пустые и офлайн-состояния. Адаптеры не падают (см. начало). Офлайн: голос → «Нет связи», подарок → откат + `errorText`,
  настройки → «СЕРВЕР» выкл, группа создаётся локально (код появится после синхронизации — кнопки копирования скрыты).
  Пустые списки ничего не показывают (как в макетах), у темы — «Пока пусто».
