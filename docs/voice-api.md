# Голосовые команды: контракт между сервером и приложением

Приложение уже работает с этим форматом через локальную заглушку (`mobile/src/lib/mockParser.ts`).
Сервер (`POST /voice`, `POST /voice/text`) должен возвращать то же самое в поле `result`.

ИИ ничего не выполняет сам: он только раскладывает фразу по схеме. Выполняет приложение, и только после подтверждения в карточке.

## Контекст, который сервер передаёт модели

- сегодняшняя дата, день недели, часовой пояс, календарь на 4 недели вперёд («пт 25.09, сб 26.09, …»);
- имя говорящего и имена участников его групп;
- **для изменений:** список существующих записей с `id` и названием — дела и «Смотреть» текущей группы, свои хотелки и последние 60 своих идей. Модель выбирает `id` только из этого списка;
- свои темы идей и тема, открытая на экране (`topicId` в запросе): идея без названной темы ложится в неё.

## Варианты ответа

| `intent` | Пример фразы | Содержимое |
| --- | --- | --- |
| `add` | «В субботу в семь ужин у родителей» | `items[]`: `{type: task\|wish\|watch, ...поля}` |
| `add` (идея) | «Запиши идею: в виджете показывать погоду», «Добавь в поздравления с Новым годом стих про кролика» | `{type: idea, text, topic}` — текст почти дословно; тема из моих (по названию или по смыслу) или новая, если прозвучала во фразе; иначе «Без темы» |
| `add` (тема) | «Создай тему идеи для подарков» | `{type: topic, title}` |
| `query_ideas` | «Покажи идеи для подарков» | `topic` → открывается тема |
| `update` | «Перенеси дачу на воскресенье», «Переименуй лампочки в …», «Перенеси идею про погоду в приложение» | `target`, `patch`: только меняемые поля (`title`, `date`, `time`; у идеи — `topic`) |
| `mark` | «Мы посмотрели Интерстеллар», «Сделал оплату интернета», «Мне подарили наушники» | `target` |
| `unmark` | «Верни дачу», «Сними отметку с Дюны» | `target` |
| `delete` | «Удали ужин у родителей» | `target` |
| `query_watch` | «Что-нибудь смешное зарубежное» | `filters` |
| `query_wish` | «Что подарить Маше?» | `person` |
| `query_plans` | «Какие у нас с Кариной планы на субботу?», «Что у друзей на выходных?», «Когда у нас дача?» | `scope` (us / people / category / groups / current), `from`, `to`, `query` |
| `unknown` | — | — |

`target` = `{ type, candidates: [id, …] }` — до трёх подходящих записей, лучшая первой.
Если подходят несколько («Забрать посылку» и «Забрать документы» на «забрать»), приложение просит выбрать.

Одна фраза может содержать несколько действий — тогда `actions[]` из элементов выше.

## Проверки на сервере (код, не ИИ)

1. Ответ проходит схему (Zod). Нет — один повтор, затем `unknown`.
2. Все `id` в `candidates` существуют и доступны пользователю. Чужие и выдуманные отбрасываются; пусто → «Не нашёл …».
3. Хотелки меняет только владелец.
4. Даты: не в прошлом (кроме явного «вчера»), время «в семь» без уточнения → 19:00.

## Что показывает приложение

| Ответ | Экран |
| --- | --- |
| `add` | карточка с записями → «Сохранить» |
| `update` / `mark` / `unmark` / `delete` | карточка «было → стало» или «Удалить: …» → «Применить» / «Удалить» (удаление можно отменить 5 с) |
| `query_*` | сразу переход на экран с фильтром / человеком |
| не найдено | «Не нашёл «…» в списках» |
| `unknown` | «Не понял. Добавить как дело / хотелку / фильм?» |

## Вопросы о планах

ИИ возвращает только «чьи» и «на какой период». Группы и дела выбирает приложение (`mobile/src/lib/plans.ts`):

- `us` («мы», «у нас») — группы категории «Пара»; если такой нет — текущая группа;
- `people` («у нас с Кариной») — самая маленькая группа, где есть вы и все названные; при равенстве — все такие;
- `category` («наши друзья») — все группы этой категории, показываются вместе, по разделам;
- `groups` — по названию группы;
- `query` («когда дача») — поиск по названию и описанию дел, включая дела без даты.

Категории групп: Пара, Семья, Родители, Друзья, Другое — выбираются при создании и в настройках группы.
